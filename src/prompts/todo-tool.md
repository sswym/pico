使用此工具在当前会话中跟踪多步骤工作。列表会显示在状态栏和 todo 面板中，帮助用户跟踪你的进度；不要为了展示进度而把 todo 列表重复写进回复正文。

## 何时使用

- 3+ 个不同步骤的任务
- 你可能会忘记某一步的任务（跨文件重命名、多功能工作）
- 用户提供要做的事情列表（编号或逗号分隔）
- 你在任务中途发现新的后续工作——追加它

## 何时不使用

- 单个简单步骤（一次编辑、一次 bash、一次 read）
- 纯问答或解释
- 少于 3 个实际步骤

## 规则

1. **每个项目有两种形式**：
   - `content`：祈使句——"修复认证 bug"
   - `activeForm`：现在进行时——"正在修复认证 bug"
2. **状态值**：`pending` | `in_progress` | `completed`。
3. **同时恰好一个 in_progress**。在开始下一个之前*先*将前一个标记为完成。
4. **（可选）`phase` 分组**：为多阶段工作（如"实施"/"验证"）给每条目加 `phase` 字段——同一 phase 的条目在 todo 面板中归入同一树分支并带阶段进度（`I. 实施 · 2/7`）。一次性任务可省略 phase。phase 名简短（≤64 字符）。
5. **仅在完全完成时标记完成**——测试通过、文件写入等。不要因为厌倦查看就认为完成。测试失败、实现不完整、有未解决的错误、找不到必要的文件或依赖——这些情况下**不**得标记完成。
6. **被阻塞时**：保持当前条目 in_progress，并新建一个条目描述需要解决的问题。不要删除被阻塞的条目假装它不存在。
7. **每次都传递完整列表**——工具替换而非补丁。删除不再相关的条目。
8. **当每个项目都完成时**，下一次调用会自动将列表折叠为空；你不需要手动清除。

## 示例

**该用**："实现这些功能：用户注册、商品目录、购物车、结算流程" → 每个功能建一个条目。用户明确列出多项任务，逐条跟踪保证不遗漏。

**该用**：跨文件重命名符号 → 为每个需要更新的文件建条目。步骤多且容易漏，todo 是防遗漏的清单。

**该用**：多文件功能开发（新建模块 + 修改入口 + 运行验证）→ 每个文件改动与每个验证阶段各建一条，todo 面板让用户实时看到阶段进度，而不是长时间黑盒等待。

**不该用**："怎么打印 Hello World？" → 单步琐碎问答，直接回答，无跟踪价值。

**不该用**："运行 npm install 然后告诉我结果" → 单次命令执行，立即出结果，不需要多步跟踪。

## 使用纪律

- **内容文本即标识符**：`content` 保持稳定，一次引入后不要改写措辞——后续更新靠它辨认条目。条目标题 5-10 个词，写"做什么"而不是"怎么做"。
- **绝不单独为 todo 调用浪费一个回合**：把 todo 操作与回合里的真实工作一起调用——首次 `todoWrite` 与第一批 read/编辑同时进行，每个 `completed` 与下一个动作同批。回合里唯一的工具调用是 todo，等于白跑一轮。
- **用户给了多步计划时**（编号/项目符号清单、"N 个 bug/事项"），先把**每一项**都建为独立条目再开工。逐条全部列出，绝不总结归并成更少的任务、抽样"重要的几个"、丢项，或靠记忆跟踪其余部分。
- **发现新的后续工作** → 立即追加，别等。
